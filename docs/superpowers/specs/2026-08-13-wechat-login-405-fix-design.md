# 微信登录 405 修复设计

## 背景与根因

生产小程序当前编译出的 API 基地址为 `https://weiyuantool.com/ganwanle-api`。该地址会由 Nginx 以 HTTP 301 重定向到 `https://www.weiyuantool.com/ganwanle-api`。微信小程序请求库跟随这次重定向时，将微信登录请求从 `POST` 改成了 `GET`；FastAPI 的 `/api/v1/auth/wechat` 按设计只接受 `POST`，因此返回 405 `Method Not Allowed`。

直接访问带 `www` 的登录地址并使用 `POST` 可以进入微信登录处理逻辑，证明后端路由和反向代理目标正常。

## 方案

生产构建必须直接使用规范地址 `https://www.weiyuantool.com/ganwanle-api`，避免认证请求经过会改变方法的重定向。登录接口继续只接受 `POST`，请求体继续以 JSON 传递临时微信登录凭证。

不采用以下方案：

- 不让登录接口接受 `GET`，避免把认证凭证放入 URL，也不改变接口语义。
- 不在本次修复中调整全站 Nginx 重定向状态码，因为该配置影响其他业务，且前端使用规范地址即可消除本故障。

## 代码与构建

- 在 Taro 生产配置中提供规范的生产 API 基地址。
- 保留 `TARO_APP_API_BASE_URL` 环境变量覆盖能力，便于不同环境部署。
- 开发构建继续使用本地默认地址，不受生产修复影响。
- 重新生成微信小程序 `dist/` 产物，供微信开发者工具加载。

## 测试与验收

- 增加构建配置回归测试，验证生产环境默认地址包含 `www`，且显式环境变量仍能覆盖默认值。
- 保留现有会话测试，验证微信登录调用使用 `POST` 并携带 `{ code }`。
- 运行前端全量单元测试和微信小程序生产构建。
- 检查生成产物包含 `https://www.weiyuantool.com/ganwanle-api`，且不再包含无 `www` 的旧生产地址。
- 通过公网探测验证规范地址的 `POST` 不发生重定向，并能到达后端微信登录处理逻辑。

## 成功标准

微信开发者工具加载新产物后，登录请求直接以 `POST` 访问带 `www` 的接口，不再出现由 301 方法转换引发的 405。
