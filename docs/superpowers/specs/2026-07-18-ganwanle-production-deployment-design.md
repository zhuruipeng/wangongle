# 干完了生产部署设计

日期：2026-07-18

## 目标

将“干完了”微信小程序后端部署到 `weiyuantool.com` 所在服务器，支持首年数百名师傅长期使用。任何微信用户都可注册成为师傅，但每位师傅只能访问自己的服务单、照片、录音、报告和客户验收数据。

## 当前环境

- 服务器：OpenCloudOS，公网地址 `124.223.174.129`。
- 资源：8GB 内存、80GB 系统盘；当前约有 5.5GB 可用内存和 64GB 可用磁盘，无 swap。
- 公网入口：Nginx 1.26.3 监听 80/443。
- 现有服务：ERP、AI 前后端分别监听本机 8000、8010、3010；Redis 监听本机 6379。
- 可用端口：127.0.0.1:8001。
- 当前后端：FastAPI、SQLite、本地上传目录，无登录、鉴权和多用户数据隔离。

## 总体架构

```text
微信小程序
    │ HTTPS
ganwanle-api.weiyuantool.com
    │
Nginx（独立 server 块与证书）
    │
FastAPI（systemd，2 个 worker，127.0.0.1:8001）
    ├── PostgreSQL：用户、服务单、报告、文件索引和登录凭证
    ├── Redis：登录与高风险接口限流、短期状态
    └── 腾讯云 COS：照片、签名和录音文件
```

新后端使用独立子域名、Linux 用户、systemd 服务、Nginx 配置、数据库和日志。现有 `weiyuantool.com` ERP/AI 路由保持不变。

## 域名与网络

- 新增 A 记录：`ganwanle-api.weiyuantool.com` 指向 `124.223.174.129`。
- 为该子域名单独签发并自动续期 HTTPS 证书。
- 微信公众平台中将该 HTTPS 域名加入 request、uploadFile 和 downloadFile 合法域名。
- Nginx 监听公网 80/443；FastAPI、PostgreSQL、Redis 仅监听回环地址。
- 云防火墙和系统防火墙不开放 8001、5432、6379。
- Nginx 将请求 ID、真实客户端地址和原始协议传给 FastAPI，并配置上传大小、超时、限流及安全响应头。

## 微信登录与账号

1. 小程序调用 `wx.login()` 获得一次性临时 code。
2. 后端通过微信服务端接口使用 AppID 和 AppSecret 换取 openid；AppSecret 只存在服务器环境变量中。
3. openid 第一次出现时自动创建 `technician` 用户，不需要邀请或管理员审批。
4. 新用户首次进入业务页面前必须填写师傅姓名；手机号暂不强制。
5. 后端签发 2 小时访问令牌和 30 天刷新令牌。刷新令牌每次使用后轮换，数据库只保存其摘要；退出登录会撤销当前刷新令牌。
6. 登录、刷新令牌和文件上传接口使用 Redis 限流；日志不得记录临时 code、令牌、AppSecret 或云服务密钥。

openid 在当前小程序内唯一。数据模型预留 unionid 和手机号字段，但首期不依赖这两个字段。

## 数据隔离与授权

核心关系如下：

```text
User
 └── ServiceOrder（owner_user_id）
      ├── Photo
      ├── Audio
      ├── Report
      └── CustomerAcceptance
```

- `users` 保存微信身份、角色、师傅姓名、账号状态和时间戳。
- `service_orders` 必须包含不可为空的 `owner_user_id` 外键。
- 照片、录音、报告和验收记录通过服务单归属到用户。
- 所有读取、修改、删除、上传、识别和报告生成接口都在数据库查询中同时约束资源 ID 与当前用户 ID。
- 后端返回 404 隐藏不属于当前用户的资源是否存在，避免枚举其他师傅的数据。
- 当前只有 `technician` 角色；保留角色字段供以后增加管理员后台，不在首期实现跨用户管理能力。

## 数据库

- 使用本机 PostgreSQL，创建独立数据库、独立低权限账号，仅监听 127.0.0.1。
- 使用版本化迁移管理表结构；应用启动不再通过 `create_all` 隐式修改生产数据库。
- 首期使用 SQLAlchemy 连接池和 2 个 FastAPI worker，满足数百名师傅的预期规模。
- SQLite 仅保留给本地开发和测试；生产环境不使用 SQLite。
- 每日生成 PostgreSQL 备份，保留最近 7 个每日备份和最近 4 个每周备份；备份必须复制到服务器之外并定期执行恢复演练。

## 文件存储与生命周期

- 正式开放前开通腾讯云 COS，使用私有存储桶。
- 对象键按环境、用户、服务单、文件类型和随机 ID 分层，不包含客户姓名、电话或原始文件名。
- 照片、签名长期保留；录音在识别成功后保留 7 天，由 COS 生命周期规则自动删除。
- 数据库保存对象键、文件类型、大小、校验值、所有者和生命周期状态，不保存永久公开 URL。
- 客户端访问私有文件时由后端完成授权，返回短时有效的签名地址或由后端受控转发。
- COS 密钥只存在服务器环境变量中，不写入小程序、Git、日志或错误响应。
- 在 COS 开通前允许真机联调临时使用服务器本地存储，但不得将其视为正式数据保存方案。

## 服务器目录与进程

- 代码版本：`/opt/ganwanle/releases/<release-id>`。
- 当前版本软链接：`/opt/ganwanle/current`。
- Python 虚拟环境随版本创建，依赖必须锁定。
- 配置文件：`/etc/ganwanle/ganwanle.env`，权限仅允许服务账号读取。
- systemd 服务：`ganwanle-api.service`，使用独立无登录 Linux 用户，工作目录指向 `current`，监听 `127.0.0.1:8001`，运行 2 个 worker，异常自动重启。
- Nginx 配置：`/etc/nginx/conf.d/ganwanle-api.conf`，独立于现有 `caiwu-erp.conf`。
- 日志交给 journald 和 Nginx 日志轮转管理，禁止把日志长期写入发布目录。
- 增加 2GB swap，降低现有多个 Python/Node 服务并行运行时突发内存不足的风险。

## 发布与回滚

1. 从指定 Git 提交创建新的只读发布目录。
2. 创建虚拟环境并安装锁定依赖。
3. 运行静态检查、自动化测试和数据库迁移预检。
4. 备份数据库，执行单实例数据库迁移。
5. 在临时端口启动新版本并检查 `/api/health` 与数据库连接。
6. 将 `current` 软链接原子切换到新版本并重启 systemd 服务。
7. 从公网 HTTPS 域名执行健康检查、登录检查、数据隔离检查和上传检查。
8. 发布失败时切回上一个发布目录；若迁移不可向后兼容，则执行对应的迁移恢复步骤。

数据库迁移采用向后兼容优先的 expand/contract 方式，避免代码回滚后无法读取数据库。

## 监控与告警

- 健康检查覆盖应用进程和 PostgreSQL 连接，但不泄露版本、密钥或内部路径。
- 监控 systemd 服务状态、HTTP 5xx、登录失败率、请求耗时、磁盘、内存、swap、数据库容量、COS 上传失败和证书到期时间。
- 磁盘使用率达到 70% 告警、85% 严重告警。
- 对登录、文件上传、语音识别和 AI 报告生成记录结构化审计事件；事件只保存用户 ID、资源 ID、结果、请求 ID 和时间，不保存完整客户隐私或密钥。

## 安全边界

- 当前开发后端在完成微信登录、逐资源授权和 PostgreSQL 迁移前不得暴露到公网。
- AppSecret、腾讯云 ASR 密钥、百炼 API Key、COS 密钥和数据库密码统一由服务器环境变量注入。
- 上传文件必须同时验证 MIME 类型、扩展名、大小和归属；下载私有文件必须鉴权。
- API 错误响应不返回堆栈、SQL、内部路径、第三方响应原文或秘密信息。
- SSH 保持密钥登录；后续限制管理来源地址并禁用密码登录。
- 开放注册不等于开放数据：所有业务资源始终按当前用户隔离。

## 测试与验收

上线前必须通过以下验证：

- 微信 code 登录成功、无效 code 被拒绝、刷新令牌轮换和退出撤销有效。
- 两个测试师傅互相无法读取、修改、删除或上传到对方服务单。
- 服务单、照片、录音、报告和验收完整流程通过。
- 超限文件、伪造类型、未认证请求和越权请求被拒绝。
- PostgreSQL 迁移可在全新数据库执行，备份可恢复到独立测试库。
- COS 私有对象不能匿名访问，授权访问会过期，录音生命周期为 7 天。
- Nginx 公网 HTTPS 健康检查、微信合法域名和真机请求通过。
- 重启应用和服务器后服务自动恢复，已有数据不丢失。
- 回滚演练能恢复上一应用版本。
- 现有 ERP 与 AI 的域名、路由和进程在部署前后保持可用。

## 分阶段上线

1. 完成认证、数据隔离、PostgreSQL、COS 和自动化测试。
2. 配置 DNS、证书、Nginx、systemd、数据库、备份和监控。
3. 使用独立测试微信账号完成公网和真机验收。
4. 邀请少量师傅试用，观察错误率、性能、存储和业务流程。
5. 修复试用问题后向所有师傅开放注册。

## 不在首期范围

- 管理员后台和跨师傅数据管理。
- 强制绑定手机号、短信验证码登录或企业组织架构。
- 多服务器、高可用 PostgreSQL、Kubernetes 或自动水平扩容。
- 正式生产数据继续使用 SQLite 或服务器本地上传目录。

## 完成标准

- `ganwanle-api.weiyuantool.com` 通过有效 HTTPS 提供服务。
- 任何微信用户可自动注册为师傅，并只能访问自己的数据。
- PostgreSQL、Redis 和 COS 按本设计工作，录音 7 天自动删除。
- 服务由 systemd 管理，可监控、可备份、可恢复、可回滚。
- 真机完成核心交付流程，现有 ERP 和 AI 服务不受影响。
